# انتخاب و تغییر «نام بسته» (Package Name) — گام به گام

## ۱) نام بسته چیست و چرا مهم است؟

نام بسته (یا `applicationId`) **شناسه‌ی یکتای برنامه** در گوشی و در فروشگاه است:

- گوشی دو برنامه را با همین شناسه از هم جدا می‌کند → دو نسخه با شناسه‌های مختلف می‌توانند کنار هم نصب شوند.
- در بازار/مایکت/گوگل‌پلی، **کلید یکتای برنامه** است و بعد از انتشار **قابل تغییر نیست** (اگر عوض کنید، استور آن را برنامه‌ی جدید می‌بیند و کاربران آپدیت نمی‌گیرند).
- در لینک استور دیده می‌شود: `https://cafebazaar.ir/app/ir.shoma.naghshe`

### قوانین نام‌گذاری
| قانون | درست | غلط |
|---|---|---|
| فقط حروف کوچک انگلیسی، رقم و `_` | `ir.shoma.map3d` | `Ir.Shoma.Map` / `ir.shoma-map` |
| حداقل دو بخش با نقطه | `ir.shoma.naghshe` | `naghshe` |
| هر بخش با حرف شروع شود | `ir.shoma.a1` | `ir.shoma.1map` |
| فارسی/فاصله ممنوع | `ir.shoma.naghshe` | `ir.شما.نقشه` |
| نام برند/شرکت دیگران ممنوع | `ir.shoma.naghshe` | `com.autonavi.minimap` |

### پیشنهاد نام برای این برنامه
اگر دامنه/برند دارید، همان را برعکس کنید. چند نمونه‌ی خوب:

```
ir.shoma.naghshe          ← ساده و فارسی‌پسند (توصیه‌شده)
ir.shoma.iranamap
ir.naghsheh.iran
com.yourname.iranmap
```

> **هشدار مهم:** نام پیش‌فرض پروژه `com.iranamap.real` است. آن را برای آزمایش نگه دارید، اما **قبل از انتشار عمومی** عوض کنید تا با هیچ برنامه‌ی دیگری تعارض نداشته باشد.

## ۲) دو مفهوم که نباید اشتباه گرفته شوند

| مفهوم | در فایل `app/build.gradle.kts` | چه چیزی را تعیین می‌کند | تغییرش لازم است؟ |
|---|---|---|---|
| `applicationId` | `defaultConfig { applicationId }` | شناسه‌ی نهایی برنامه در گوشی/استور | ✅ بله |
| `namespace` | `namespace` | فضای نام کد و کلاس `R` و نام پوشه‌ها | ❌ معمولاً نه |

یعنی برای انتشار در فروشگاه **فقط `applicationId` کافی است**؛ `namespace` می‌تواند همان `com.iranamap.real` بماند و هیچ مشکلی ایجاد نمی‌کند (گوگل هم همین را توصیه می‌کند).

## ۳) روش الف — تغییر فقط `applicationId` (ساده‌ترین، کم‌خطرترین) ✅ توصیه‌شده

### با اسکریپت (یک دستور)

```bash
./scripts/set_package_name.sh ir.shoma.naghshe --id-only
```

### یا دستی (۱۵ ثانیه)

فایل `app/build.gradle.kts` را باز کنید، این خط را پیدا کنید:

```kotlin
val appId: String = (project.findProperty("appId") as String?) ?: "com.iranamap.real"
```

و مقدار پیش‌فرض را عوض کنید:

```kotlin
val appId: String = (project.findProperty("appId") as String?) ?: "ir.shoma.naghshe"
```

همین. تمام. کد، پوشه‌ها و `R` دست‌نخورده می‌مانند.

### یا حتی بدون ویرایش فایل (فقط برای ساخت)

```bash
./gradlew assembleDebug -PappId=ir.shoma.naghshe
APP_ID=ir.shoma.naghshe ./scripts/build_apk.sh
```

> این گزینه برای وقتی است که از **یک کد**، چند نسخه (مثلاً نسخه‌ی رایگان و نسخه‌ی کامل) می‌سازید.

## ۴) روش ب — تغییر کامل (applicationId + namespace + پوشه‌ها)

اگر می‌خواهید نام پوشه‌ها و importها هم برند شما شوند:

```bash
./scripts/set_package_name.sh ir.shoma.naghshe
```

این اسکریپت:
1. نام بسته را اعتبارسنجی می‌کند (حروف کوچک، حداقل دو بخش، بدون نام برندهای دیگر).
2. از فایل‌های حساس **پشتیبان** می‌گیرد.
3. `applicationId` و `namespace` را عوض می‌کند.
4. پوشه‌های `app/src/main/java/com/iranamap/real` و `app/src/test/java/...` را جابه‌جا می‌کند.
5. همه‌ی `package`ها، `import`ها و ارجاع‌های `proguard` را به‌روزرسانی می‌کند.
6. بررسی می‌کند چیزی از نام قدیمی نمانده باشد و در پایان اعتبارسنجی منابع را اجرا می‌کند.

نمونه‌ی خروجی واقعی (آزمایش‌شده):

```
✔ پوشه منتقل شد: app/src/main/java/com/iranamap/real → app/src/main/java/ir/shoma/naghshe
✔ 66 فایل به‌روزرسانی شد (package/import/R/proguard)
✔ هیچ ارجاعی به نام قدیمی نماند.
✓ هیچ خطایی در منابع و ارجاع‌ها یافت نشد.
```

بازگشت در صورت اشتباه:

```bash
tar -xzf "/tmp/iranamap-package-backup-XXXXXXXX.tar.gz"
```

### روش ج — Android Studio

`پوشه‌ی java/com/iranamap/real` را راست‌کلیک کنید → `Refactor ▸ Rename` → گزینه‌ی `Rename package` را انتخاب و نام جدید را وارد کنید. سپس `applicationId` را هم مطابق بخش ۳ عوض کنید.

## ۵) نسخه‌ی برنامه و آپدیت‌ها

در همان `app/build.gradle.kts`:

```kotlin
versionCode = 3          // عدد صحیح؛ برای هر انتشار در استور +۱ شود
versionName = "3.0.0-fa" // متنی که به کاربر نشان داده می‌شود
```

| انتشار | versionCode | versionName |
|---|---|---|
| اولین انتشار | ۳ | 3.0.0-fa |
| رفع باگ | ۴ | 3.0.1-fa |
| امکانات جدید | ۵ | 3.1.0-fa |

> استور **فقط** به `versionCode` نگاه می‌کند: اگر آن را بیشتر نکنید، آپدیت رد می‌شود.

## ۶) چک‌لیست بعد از تغییر نام بسته

- [ ] `./scripts/build_apk.sh` بدون خطا تمام شد.
- [ ] برنامه‌ی قبلی را از گوشی **حذف** کنید (شناسه عوض شده؛ نسخه‌ی جدید کنارش نصب می‌شود و ممکن است دو آیکون ببینید).
- [ ] در `تنظیمات ▸ برنامه‌ها` نام بسته‌ی جدید را ببینید.
- [ ] اگر نسخه‌ی release می‌سازید، با کلید جدید امضا کنید (فایل `.jks`).
- [ ] `versionCode` را برای انتشار بعدی بالا ببرید.
- [ ] در بازار/مایکت، نام بسته را از پیش بررسی کنید که آزاد باشد.

---

## ۷) خطاهای رایج

| خطا | علت | راه‌حل |
|---|---|---|
| `Namespace not specified` | `namespace` در `build.gradle.kts` پاک شده | آن را دوباره اضافه کنید یا اسکریپت را دوباره اجرا کنید |
| `Unresolved reference: R` | پوشه‌ها جابه‌جا شده ولی `package`ها نه | `./scripts/set_package_name.sh <همان نام>` را از نسخه‌ی پشتیبان دوباره اجرا کنید |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | با کلید امضای دیگری نصب شده | `adb uninstall <نام بسته>` سپس نصب مجدد |
| دو آیکون روی گوشی | شناسه‌ی جدید در کنار قدیمی نصب شده | قدیمی را حذف کنید |
| استور آپدیت را قبول نمی‌کند | `versionCode` بالا نرفته | آن را +۱ کنید |
